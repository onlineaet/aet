# AET 编译器 泛型实现：泛型块+二次编译 



## 引言

泛型（Generics）已经成为现代编程语言的重要组成部分。

目前主流语言主要采用两种实现方式：

-   **C++ Template（通常采用 Template Instantiation / Monomorphization思路）**
-   **Java 泛型（类型擦除）**

AET 没有采用其中任何一种方案，而是在实现编译器过程中形成了一种新的实现思路：

> **泛型块 Generic Block + 二次编译 Two-pass Compilation（Delayed Specialization，延迟特化）**

它希望在保持较小代码体积的同时，仍然保留真正的类型能力。

------------------------------------------------------------------------

## 为什么 AET 不采用 C++ Template？

大多数 C++ 编译器最终采用类似 **Template Instantiation（Monomorphization）** 的方式，为不同类型生成独立代码。

优点：

-   编译期即可得到真实类型
-   优化能力强
-   没有运行期开销

缺点：

-   编译时间增加
-   二进制膨胀
-   模板实例数量巨大时维护成本高

AET 希望避免 Template Explosion。

------------------------------------------------------------------------



## 为什么 AET 不采用 Java的类型擦除？

Java 泛型实现的方案是类型擦除。

优点：

-   各版本兼容
-   内存占用低
-   避免代码膨胀

缺点：

-   真实类型被擦除
-   类型相关操作能力有限

AET 作为系统级语言，希望同时保留编译期类型安全和具体类型能力，因此没有采用擦除方案。

------------------------------------------------------------------------



## AET 的思路：延迟特化

AET 希望做到：

> **既不要 Template Explosion，也不要 Type Erasure。**

因此采用：

> **Generic Block + Two-pass Compilation（Delayed Specialization）**

第一次编译：

-   普通泛型统一处理为 `void *`
-   保留泛型信息
-   保存 Generic Block 源代码

第二次编译：

- 当发现具体实例（如 `Abc<int>`）

- 重新生成 Generic Block

- 将 `E` 替换为真正类型

## 泛型块：AET 泛型的核心

普通泛型第一次编译会把 `E` 转换为 `void *`。

只有 `genericblock$` 内部才进行真正的类型特化，例如：

``` c
genericblock$(a){
    E x=a;
    E y=5;
    x+=y;
}
```

或：

``` c
genericblock$(obj){
    E value=obj;
    value->walk();
}
```

这里必须知道 `E` 的真实类型，否则编译器无法生成正确代码。

------------------------------------------------------------------------



## 为什么必须二次编译？

第一次编译时：

``` c
void setData(E value)
```

编译器知道：

    E

但不知道：

    E=int

因此只能生成：

``` c
void *
```

直到程序出现：

``` c
Abc<int> *a=new$ Abc();
```

编译器才知道：

    E=int

随后重新解析泛型块，并把其中所有 `E` 替换成 `int`。

这就是 **二次编译**

------------------------------------------------------------------------



## 编译器内部实现

1.  AST 保存泛型信息（`_generic_1234_array`）。
2.  保存泛型块原始源码。
3.  生成占位函数调用。
4.  第二次编译时重新解析泛型块。
5.  完成 Delayed Specialization。

------------------------------------------------------------------------



## 总结

AET 的泛型既不是 C++ Template，也不是 Java类型擦除。

它采用：

> **Generic Block + Two-pass Compilation（Delayed Specialization）**

整个函数不会因为泛型实例化而重复生成，只有真正需要具体类型的 Generic
Block 才进行最后一次类型特化。

这样希望在以下几个目标之间取得平衡：

-   避免 Template Explosion；
-   保留完整类型能力；
-   将类型特化限制在最小范围。
