### 2. 实现泛型三级函数内联

完善 AET 泛型块的代码生成和内联机制，实现：

```text
fwgb（带泛型块函数）
    ↓
genericblock$
    ↓
compareFunc（比较函数）
```

例如：

```c
impl$ APriorityQueue
{
   ...
   public$ void push(E x) {
      genericblock$(x){
         ...
         if(((ProrityCompare)compareFunc)(&x,&e))
            break;
         ...
      };
   }
   ...
};
```

调用：

```c
APriorityQueue<int,MinHeapFunc> *apq =
    new$ APriorityQueue(N, intComparator_cb);

for (int i = 0; i < N; ++i)
    apq->push(data[i]);
```

编译器在具体类型确定后生成专门的泛型块函数，例如：

```c
static inline void
_int_0_MinHeapFunc_0_aet_util_APriorityQueue__gen_block_func_1(
    aet_util_APriorityQueue *self,
    aet_generic_E _aetGenNewParamPrefix_x)
```

最终使：

```text
apq->push(data[i])
    ↓
push
    ↓
genericblock
    ↓
compareFunc
```

能够进入同一个优化上下文，实现泛型代码的多级内联。这也是 AET Delayed Specialization 在实际泛型容器中的进一步应用。

### 4. 修复泛型返回值问题

修复如下情况：

```c
E getData(){
   return NULL;
}
```

当 `E` 在非泛型块中被擦除为 `void *` 时：

```c
return NULL;
```

是合法的。

但当 `E` 在第二阶段被实例化为值类型时，返回 `NULL` 就会产生错误语义。

AET 现在将其转换为：

```c
generic_is_pointer(E)
    ? NULL
    : _aet_generic_zero_storage
```

其中 `generic_is_pointer(E)` 在泛型实例化后可以确定 `E` 是指针类型还是值类型。

`_aet_generic_zero_storage` 为全局零初始化存储空间，其大小根据整个项目中泛型值类型的最大尺寸确定。

同时：

- `.so` 中的 `_aet_generic_zero_storage` 使用 weak symbol
- 最终可执行文件中使用 strong symbol

从而允许最终程序中的定义覆盖 `.so` 中的定义。

### 5. 修复泛型常量参数生命周期问题

修复：

```c
void setData(E value);

setData(5);
```

由于泛型参数 `E` 在第一阶段被擦除为 `void *`，常量 `5` 需要转换为临时对象地址：

```c
setdata(({ int a = 5; &a; }));
```

原实现可能产生：

```text
warning: using a dangling pointer to ‘a’
```

现在编译器在调用 `setData` 的当前函数体中生成：

```text
_temp_generic_const_var_xxx
```

并将其插入当前函数体的第一条语句，使临时变量具有足够的生命周期。

相关实现位于：

```text

```
