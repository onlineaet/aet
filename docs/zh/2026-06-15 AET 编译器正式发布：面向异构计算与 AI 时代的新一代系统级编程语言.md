## AET 编译器正式发布：面向异构计算与 AI 时代的新一代系统级编程语言

###  —— 一次编写，多芯运行；让编译器连接 CPU、GPU 与未来 AI 芯片

经过长期开发和测试，今天正式发布 **AET（Active Expandable Translator）编译器项目**。

AET 是一个基于 GCC 构建的新型编译器系统，同时也是一门面向异构计算的系统级编程语言。

它的目标：

> 让开发者使用统一的语言模型开发高性能程序，并通过编译器将代码扩展到 CPU、GPU 以及未来 AI 加速设备。

项目地址：

### 为什么需要新的编译器？

过去几十年，软件开发经历了多个阶段：

C 解决了系统性能问题。

C++ 提供了大型软件工程能力。

CUDA 推动了 GPU 通用计算。

Python 和 AI 框架降低了人工智能开发门槛。

但是今天的计算环境正在发生变化。

一个现代 AI 程序通常包含：

```
Python算法代码
       ↓
C/C++底层框架
       ↓
CUDA GPU Kernel
       ↓
硬件执行
```

![点击并拖拽以移动](data:image/gif;base64,R0lGODlhAQABAPABAP///wAAACH5BAEKAAAALAAAAAABAAEAAAICRAEAOw==)

开发者需要同时面对：

- CPU 编程模型
- GPU 编程模型
- 不同硬件 API
- 不同优化方式

随着 GPU、NPU、AI 芯片越来越多，软件和硬件之间的距离正在增加。

AET 希望探索另一种方向：

> 让异构计算成为编译器能力，而不是开发者手动拼接不同语言。

### AET：基于 GCC 的新型编译器系统

AET 没有重新实现一个简单解释器，而是选择深入 GCC 编译体系。

当前版本基于：

- GCC 15.2
- GIMPLE 中间表示
- RTL 后端
- NVPTX GPU 后端

传统 GCC：

```
Source
 ↓
Frontend
 ↓
GIMPLE
 ↓
RTL
 ↓
Machine Code
```

![点击并拖拽以移动](data:image/gif;base64,R0lGODlhAQABAPABAP///wAAACH5BAEKAAAALAAAAAABAAEAAAICRAEAOw==)

AET 扩展：

```
AET Source
 ↓
AET Frontend
 ↓
GCC IR
 ↓
Backend
 ↓
CPU / GPU Code
```

![点击并拖拽以移动](data:image/gif;base64,R0lGODlhAQABAPABAP///wAAACH5BAEKAAAALAAAAAABAAEAAAICRAEAOw==)

这意味着：

AET 程序不是通过运行时解释执行。

而是经过完整编译流程生成目标代码。

### AET 语言：保持 C 的性能，引入现代语言能力

AET 保留 C 语言特点：

- 高性能
- 接近硬件
- 易于优化

同时加入现代软件工程能力：

- class
- interface
- inheritance
- generic programming

例如：

```

    void train();
};

impl$ Network {
    void train(){
        printf("training\n");
    }
};
```
